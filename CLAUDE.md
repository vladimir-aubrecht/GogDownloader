# GameArchiver

Archives owned GOG and Steam games through independent provider libraries and an aggregate API.
C# / .NET 9, runs on Linux, Windows and macOS. GOG retains its original CLI and metadata.

## Language

Everything in this repository is **English**: code, comments, XML docs, commit messages,
documentation, scripts and the application's console output. Chat with the maintainer
happens in Czech, but none of that ever lands in a file.

## Before you touch the GOG API or GameVault

Read `docs/gog-api.md` and `docs/gamevault.md`. They are verified caches of facts neither
project documents. **Do not go hunting for endpoints or indexer rules on the web.** Both are
regenerated by `scripts/vendor-ref.sh [gog|gamevault|all]`.

## Architecture

- `GameArchiver.Core` owns common contracts, archive metadata, ZIP primitives, links, publication
  and storage. It never references a provider. ZIP/rate limiter types use the `GogArchiver.Core`
  namespace and are forwarded from the provider assembly to the shared assembly.
- `GogArchiver.Core` exposes `GogClient`; `SteamArchiver.Core` exposes `SteamClient` and
  uses SteamKit2 3.4.0 directly. Neither provider references the aggregator or the other provider.
- `GameArchiver` accepts `IGameStore` instances and aggregates sync/download/diff/verify.
  `GameArchiver.Cli` is the common front end. Keep the original GOG CLI working.
- Unified `archive find|add|replace` edits only metadata-referenced ZIPs, across all selected
  platforms by default. Raw-copy existing compressed entries with bounded buffers; never use
  `ZipArchiveMode.Update` for multi-gigabyte game files. Preserve replaced entries under repeated
  `.backup` suffixes. Publish to a unique `(local-<id>).zip` name, commit authoritative metadata
  last, then remove the previous archive. Update sizes/hash inventory and `ModifiedAt`, retaining
  provider selection and `CompletedAt`. Local edits are not persistent download overlays.
  Metadata writes must use the reader's authoritative file selection, never file existence alone.
  Compare normalized paths before editing a ZIP shared by platforms. Bound publication names
  to 255 UTF-8 bytes, preserve GameVault type tags and use independent short temporary names.
- The solution is `GameArchiver.sln`. Configuration/staging directories (`gogdownloader`,
  `gamearchive`), `GOGDL_SNAPSHOT`, `GAMEARCHIVE_STEAM_*` and lock filenames retain
  their existing names across the project rename. Archive metadata migration is described below.
- The unified CLI selects providers with `--source`. Output defaults to `--layout flat`;
  `--layout provider` uses `{root}/{source}/{slug}`, with repeatable `--provider-dir SOURCE=NAME`
  overrides. All download/diff/verify/orphan operations share `ProviderOutput` routing.
  Keep local staging independent of output layout and never move backups implicitly.
- `schedule --config FILE` runs validated JSON sync/download jobs sequentially. Each job must
  explicitly choose all matching games or named products. Keep partial product sync failures
  visible while allowing fresh catalog downloads; skip downloads after source-level or snapshot
  failures. Lock the shared snapshot directory, honor cancellation/SIGTERM and retain staging.
  Only caller cancellation stops the scheduler; HTTP timeouts are failures, not interruptions.
  Docker persists credentials/snapshots in `/state`, scratch in `/staging` and backups in
  `/archives`; never bake credentials or user configuration into image layers. See docs/docker.md.
- Identity is `(Source, ProductId)`, with string IDs. A slug is only a folder suggestion.
  Both providers write visible `gamearchiver.json` (no leading dot, clear Hidden). Steam uses
  schema 2; GOG retains its schema-1 payload. Detect format by Source/GameId, not filename.
  Read legacy `.gogdl.json` and `.gamebackup.json`; canonical wins for matching owners, and
  without it the GOG legacy file wins over the old unified file. Conflicting owners fail.
  Downloads, including AlreadyDone, ZIP edits and `archive migrate` migrate under an archive
  lease: preserve JSON fields, add missing GOG Source, commit canonical then remove recognized
  old files. Never touch ZIP bytes for migration; preserve explicitly foreign legacy files.
  Read-only commands do not migrate. Updated standalone GOG and shared CLIs use the same name.
- Preserve folder names by metadata identity. A new second-store copy may use `{slug}_{source}`;
  same-store/unidentified collisions fail and require an explicit alias. Never append numeric IDs.
- Steam installs are not guaranteed portable/DRM-free. Record the runtime requirement and actual
  depot/branch/language/architecture selection. Reject inaccessible/private manifests, unsafe
  paths, empty game plans and bad hashes before recording completion.
- Steam sessions, callbacks and Steam Guard interaction belong in the Steam provider; no console
  I/O in the provider APIs. Read `docs/steamkit2.md` before modifying the protocol adapter.
- An incomplete source/product sync preserves previously known entries and records failures.
  Source-filtered sync must preserve other sources' games and failures.
- Steam's full validated `GetOwnedGames` list defines primary catalog membership for normal
  library listings and batch downloads/diff. Preserve the complete license/appinfo inventory
  for DLC resolution, explicit downloads and orphan detection; `--inventory` exposes it.
  `PrimaryCatalogs` and `FailureImpacts` are optional aggregate metadata, and version
  `Dependencies` records selection provenance without changing content equality. Never clear
  a denied AppID just because it is absent from the primary catalog. Source failures preserve
  the last catalog and per-app evidence; report retained failure impacts as stale.
  Unified CLI `download --all` defaults to games (including standalone GOG game packs).
  `--include-non-games` includes supported applications/demos; explicit IDs remain selectable.
  Resolve DLC to its parent before product/DRM/size filters; owned DLC still belongs in the ZIP.
  Metadata-only refreshes must retain previous unchecked selection failures with `IsStale`
  impacts, including catalog entries that fail before selection begins. Successful appinfo
  or catalog membership is not a successful download selection.
- DRM is reported metadata, not inferred from Steam ownership or DLLs. Preserve Free/Protected/
  Unknown per store and OS, source evidence and branch scope. Manual overrides survive both
  ownership and community refreshes. Only explicit, unambiguous community evidence is free;
  unavailable/conditional/missing evidence stays unknown. Normal sync remains independent of
  PCGamingWiki. Read `docs/pcgamingwiki.md` before changing its adapter. DRM set/clear without
  a product key reads current-folder metadata (canonical or legacy), infers only an unambiguous
  platform and its branch, and saves overrides in the library snapshot. Explicit selection wins;
  conflicting ownership/source must fail. Do not mutate local archives just to annotate DRM.
  `--drm-source steam-curator` is an explicit alternative when PCGamingWiki denies access.
  Read `docs/steam-curator-drm.md` before changing its adapter. Validate the entire paginated
  list before classifying any product; missing/conditional entries are unknown, not protected.
  Keep attribution distinct from PCGamingWiki and do not infer DRM for native ports.
  PCGamingWiki auth uses bot-password login and persists only verified cookies, not passwords.
  Keep session files private from creation (0600 / current-user Windows ACL) and writes atomic.
  Authenticated DRM queries use Cargo by exact AppID and assert=user; expired sessions fail
  without anonymous fallback. Never forward API redirects or echo server login error bodies.
  Local `library drm test` is autonomous: Steam observed = Protected, game process tree still
  running without Steam at the deadline = Free, early exit/error = Unknown. Label the heuristic
  local-process-test; never prompt for gameplay. Preserve DrmTests across both syncs; manual
  overrides outrank matching local verdicts, then community evidence. Scope local results by version/selection; publication must
  validate TestedVersion against live content. Modified archives do not classify store content.
  Read docs/local-drm-tests.md before changing the runner. Checkpoint each completed attempt,
  retain unfinished work as untested, extract into fresh local scratch and leave ZIPs untouched.
  Windows jobs contain the process tree before launch for cancellation/cleanup, not sandboxing.
  Stop new Steam clients after each test before continuing. Preserve preexisting clients;
  validate pinned process handles, start times and session before cleanup. Cleanup failure
  stops the batch and preserves completed results. Observation, startup checks and cleanup
  share current-session scoping; ignore foreign sessions before opening handles. Return
  cleanup observations independently of errors/timeouts so detected Steam remains Protected.
  Historical interactive records remain readable.
- Steam `download=0` with nonzero/missing installed size is unknown, not an empty depot.
  SizeEstimateRevision 1 invalidates old compressed estimates. Small-game filtering may fall
  back to the independently recorded installed total; report its basis and exclusion reasons.
  Recheck the size limit using the
  actual selected manifest chunk total before content transfer; never bypass hash failures.

## Decisions already made (GOG compatibility)

- **Path A (primary):** Galaxy content-system depots for `windows` and `osx`. The installed
  game files are downloaded directly, chunk by chunk. No installer conversion.
- **Path B (Linux):** implemented. Galaxy has no Linux depots, so the game is read out of the
  MojoSetup installer (shell script + ZIP payload) over HTTP Range. Opening one costs about
  2 MiB regardless of its size; only `data/noarch/` is game content. See `MojoSetupReader`.
- **Path C (Inno Setup):** implemented for Windows titles with no depot — the old bundles and
  compilations. The installer cannot be read over Range, so it is downloaded next to staging,
  extracted with `innoextract` (`-e -m -g -s`), and deleted. It never reaches the archive, and
  it survives an interrupted run so a rerun does not fetch it again. This is the only external
  dependency in the project; without it those titles report how to install it.
- **Windows MAX_PATH is innoextract's problem, not ours.** The tool's own I/O is long-path aware,
  innoextract is not. So everything it touches stays short: installer parts are renamed to
  `s.exe`/`s-N.bin` (innoextract finds slices by the exe's base name, so they must be renamed
  together), and the extraction scratch is `{gameId}.x`, not a slug-length name. Real failures:
  BG3's installer filename alone was 130 chars, HoMM5's game tree blew past 260 via the prefix.
- **Snapshot depot links go stale.** GOG republishes builds; the old manifest URL then returns
  403 or 404. The downloader refetches the latest build live and carries on — a game must not
  fail over a link that `library sync` would refresh anyway. (Prehistorik and Quake were once
  blamed on this. They were packs, see below; the fallback is right, the diagnosis was not.)
- **macOS without a depot stays unsupported.** Its installers are `.pkg` inside `.dmg`, which is
  neither a depot nor Inno Setup. `diff` and `library stats` say so rather than failing later.
- **Packs are containers, and a pack of games the library owns separately is skipped.** GOG's
  `game_type: "pack"` product has no build on the content system at all, and its games are
  granted as products of their own — those are what Galaxy installs and what the backup holds.
  `library sync` records `IsPack` and, for packs only, `includesGames` from the v2 endpoint;
  `download` and `diff` then skip a pack whose games are all in the library. A pack whose games
  are **not** all there is still the only copy of them, so it downloads as before. This is what
  Prehistorik 1+2 (403) and Quake (404) really were — not stale depot links.
- **DLC:** owned DLC belongs in the zip. The DLC list is `products[]` straight from the
  repository manifest, intersected with owned ids — no extra API call. Schema 8 records it
  per platform. A separate DLC product selects its depot-backed base game, including in a
  filtered batch and in `diff`; it is not a second portable game. Installer-only backups do
  not merge DLC. See the BG3 Deluxe / Space Age / Atlantis evidence in `docs/gog-api.md`.
- **A matching build id is not enough to skip a backup.** The ZIP must exist at its recorded
  size, the language must match, and all expected owned DLC must be recorded. A newly owned
  expansion requires rebuilding the ZIP even when GOG did not change the base build.
- **InstalledSize is measured from staging.** The Inno path's three-times-installer estimate
  is only for the free-space check; it must never be recorded as the size of extracted content.
- **Sizes** live in the repository manifest (`compressedSize` = bytes downloaded, `size` = bytes
  on disk) and are recorded by `library sync`. They are language-dependent, so the snapshot
  records them for `en`, matching the default of `download --language`.
- **Snapshot schema** is versioned. When a sync starts recording something older snapshots
  lack, bump `LibrarySnapshot.CurrentSchema` and warn on read — a stale snapshot silently
  reporting zero is worse than an error.
- **Redistributables** (`dependencies` in the manifest): **not downloaded.** They are
  recorded in `gamearchiver.json` as `skippedDependencies` so it stays visible what the game wanted.
- **Archive:** zip everywhere. Symlinks are dereferenced. Preserve ordinary Unix rwx bits from
  Linux installers and executable flags from GOG/Steam depots, including dereferenced targets.
  Pass explicit modes to the writer so cross-platform downloads never depend on staging-host
  permissions. ZIP edits retain original creator/mode fields, including replacements/backups.
  Content revision 2 refreshes older Linux/macOS backups once; Windows revision-1 backups remain current.
- **GOG publication:** a colliding archive name gets a unique `(revision-<id>)` suffix. Keep the
  old ZIP until metadata commits and remove the uncommitted replacement after failure/cancellation.
  An equal version label is not equal content (language, DLC and republished builds can differ).
- **ZIP directories:** validate declared counts, sizes, offsets and complete records. ZIP64
  applies when any count/size/offset field overflows; never truncate a ZIP64 count to 16 bits.
- **Archive names follow GameVault's convention:** `Title (vVersion) (EA) (GameType).zip`, see
  `GameVaultName`. GameVault indexes recursively (`GAMES_SEARCH_RECURSIVE` defaults to true) and
  filters by extension, so the `{slug}` directory and `gamearchiver.json` beside the zip are
  both fine. Verified against gamevault-backend `files.service.ts` (f95cc9f), not just the docs.
- **No release year in the archive name.** GOG's `release_date` is not the release year: The
  Witcher 2 reports 1991, Akalabeth (1979) reports 2014, and some titles report null. GameVault
  feeds the year to its metadata matcher, so a wrong year is worse than none.
- **Staging goes on a local disk**, never in `--out`. Users back up onto network shares, and
  staging there would push every byte across the wire three times (write the files, read them
  back to zip, write the zip). Override with `--staging`. When staging and target sit on
  different volumes the zip is copied to a sibling `.tmp` and then renamed, so the final name
  still appears atomically. Staging defaults to local app data, **not** `Path.GetTempPath()`:
  on Linux temp is often a tmpfs in RAM and a large game would exhaust it.
- **Zipping is parallel per entry, and the ZIP writer is ours** (`ParallelZipWriter`). ZIP
  compresses every entry independently, so deflating entries on many cores yields a
  byte-identical archive — the ratio never changes. No maintained .NET library does this:
  `DotNetZip` is deprecated with a high-severity CVE and its parallel deflate splits a single
  stream into blocks, which *does* worsen the ratio; `SharpCompress`'s ZipWriter is sequential.
- **Every archive is read back and checked against staging before platform completion is recorded**
  (`ArchiveVerifier`, skip with `--no-verify`). `ZipFile.OpenRead` does **not** verify CRCs —
  a corrupted payload opens without complaint — so the check recomputes them from the
  decompressed bytes and compares against the source files.
- **Empty files are stored, never deflated** (`Entry.IsStored`). A `DeflateStream` that is never
  written to emits nothing, and a zero-byte deflate stream lacks its final block — so an empty
  file recorded as deflated cannot be inflated by anything. .NET reads such an entry back as
  empty without complaint, which is why `ArchiveVerifier` passed it: Duke Nukem 3D's `CDROM.INI`
  made a whole archive unreadable to Info-ZIP, 7-Zip and Windows Explorer. Fixed in 0.39.0.
- **`verify` checks archives on their own**, without the staging they were built from — that is
  what `ArchiveVerifier` needs and a months-old backup no longer has. `ArchiveCheck.Headers`
  reads the central directory (`ZipInspector`, because `ZipArchiveEntry` hides the compression
  method) and costs nothing; `--deep` inflates every entry and recomputes its CRC.
- **`verify --fix` repairs in place, and only what is provably repairable** (`ArchiveRepair`).
  The empty-deflate entry carries no payload and records zero sizes and a zero CRC, so the only
  wrong thing about it is the compression method: two bytes in the local header and two in the
  central one. Nothing moves, so a 30 GiB archive on a network share is mended in a seek — and
  the result is byte-for-byte what the fixed writer would have produced, which a probe asserts.
  The repair refuses when the local header disagrees with the central directory, because then it
  is not this defect. Payload damage is never repairable and is reported for a re-download.
- **An interrupted run asks** what to do with what it downloaded, and the next run resumes:
  files whose size and hash match are not fetched again. Neither keeping nor deleting tens of
  gigabytes is a decision to make on the user's behalf. Without a terminal there is nobody to
  ask, so the files stay; `--clean` and `--keep` answer in advance.
- **Long operations must stay interruptible.** `ZipFile.CreateFromDirectory`, `CreateEntryFromFile`
  and `File.Copy` all ignore cancellation for the length of one file, and games ship
  multi-gigabyte archives in a single file. Copy through a buffer and check the token each
  block. A cancelled run deletes its partial zip and `.tmp`.
- **Free space is checked before downloading**, not discovered an hour in, and a resume only
  asks for what is still missing. If a volume fills up anyway, nothing is deleted: the staging
  directory survives, a partial `.tmp` next to the target is removed, and rerunning resumes.
- **On Linux, a path root is not a filesystem.** `/mnt/staging` and `/mnt/nas` both start
  with `/` but may be different mounts. Query free space using the full directory path and
  choose the longest matching mount for the same-volume optimization. Unknown mounts and
  symlink/junction ancestors use the interruptible copy-to-temp path. The storage probes
  reproduce both the wrong free-space decision and the uninterruptible cross-mount move.
- **Both depot generations are supported**, behind `DepotSource`. Generation 1 is a different
  format — nested under `product`, `Neutral` instead of `*`, sizes as strings, no
  `compressedSize` — and its files are byte ranges into one `main.bin` rather than chunks. It
  is listed as `win:gen1` because the size shown is the unpacked one.
- **Reliability:** work in a staging directory, only an atomic `File.Move` into the target.
  The `gamearchiver.json` manifest reserves the directory for its `GameId` before downloading.
  Allocation holds a shared library-root reservation; ownership metadata uses `CreateNew`,
  since `File.Move(overwrite: false)` has a check/rename race on Unix. Never unlink live lock files.
  Platform completion is written **as the very last step** — until that entry exists the
  platform counts as not downloaded. A corrupted "done" state cannot arise.
- **Idempotence and patches:** the manifest carries per-file hashes, so a new build lifts every
  unchanged file out of the old zip (`ArchiveCache`) and downloads only what changed. Content is
  addressed by hash, so a moved file is still a hit, and every reused file is re-hashed —
  `ZipFile.OpenRead` does not check CRCs, so the old archive proves nothing by itself.
  Disable with `--no-reuse`. Inno Setup yields no per-file hashes, so path C cannot reuse.
- **Output directory names** are lowercase `{slug}`, with `GameId` in `gamearchiver.json`.
  Reject unsafe slugs and case-insensitive collisions in the snapshot or on disk; never
  reuse a different GameId's directory. Legacy `{slug}__{gameId}` folders are renamed on
  download after ownership checks; `diff` recognizes both without changing them. Staging
  retains its old ID-bearing key so interrupted downloads still resume.
- **Backup origin** is `Source: "gog"` in `gamearchiver.json`; absent Source in `.gogdl.json` means legacy GOG.
  The next download migrates it without rebuilding a current archive. Inspect Source before
  parsing GOG-specific fields: foreign metadata may use a different ID/platform schema.
  Unmarked folders and explicit foreign legacy sources are ignored by GOG orphan reporting
  and verification. The aggregate API and GameVault script also handle native Steam schema 2. A foreign folder occupying a GOG slug is a conflict, never
  a cache or a completed GOG backup, even if its numeric ID matches.
- **The user controls** download speed and the number of concurrent connections.
- **A launcher is written into each archive root** (`start.bat` on Windows), from the depot's own
  `goggame-{id}.info` play tasks — never guessed, so a game without metadata gets none. Linux is
  left alone: its installer already ships `start.sh`. Disable with `--no-launcher`.
- **The tool never talks to GameVault.** It records the launcher path into `gamearchiver.json`
  (`Platforms.{os}.LaunchExecutable`), which is neutral metadata. The optional
  `scripts/gamevault-sync.sh` (curl + jq, a compose sidecar) reads those and sets GameVault's
  `launch_executable` over its API. The GameVault dependency stays in that script, out of the code.

## A trap you can fall into

`api.gog.com` uses the string `mac` for macOS, but `content-system.gog.com` uses `osx`.
Do not mix them up.

## Working principles for this project

- Do not implement features until it is proven the user's library needs them. When in doubt,
  ask — do not write code just in case.
- Store expensive findings in `docs/`, do not re-derive them every session.
- Take size and count estimates from real data (`library sync`), not from memory.

## Build and verify

```sh
dotnet build
dotnet run --project src/GogArchiver.Cli -- <command>
scripts/check.sh          # build + probes + CLI against tests/fixtures/library.json
```

Note: `dotnet run -v q --nologo -- <command>` swallows the arguments. Use the form above.

`tests/GogArchiver.Probes` is a plain console app, no test framework, matching the
no-dependencies rule. Add a probe whenever a bug was subtle enough to be worth remembering —
several already exist because the obvious implementation was wrong.

Any command takes `--snapshot FILE` (or `$GOGDL_SNAPSHOT`). Use it to run against
`tests/fixtures/library.json` instead of the user's real library.

## Release

Commit and push completed, verified changes to the working branch unless the maintainer asks
otherwise. After a successful merge, remove the merged feature branch locally and remotely
once its commits are confirmed present in the target branch. Ordinary pushes do not bump
versions or create release tags. `scripts/release.sh` is for explicitly requested releases:

```sh
scripts/release.sh 0.8.0 "Subject line" <<'EOF'
Body of the commit message.
EOF
```

It bumps `Directory.Build.props`, refuses to continue when `check.sh` fails or the tag exists,
then commits, tags `vX.Y.Z` and pushes. Do not push work in progress.
